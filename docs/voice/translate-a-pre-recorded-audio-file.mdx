The Voice Translate Job API translates pre-recorded audio files asynchronously. You submit a file, DeepL processes it, and you download the results when they're ready. This guide walks through the complete workflow: creating a job, uploading your audio, polling for completion, and downloading the output.

Use this API for pre-recorded content like podcasts, meeting recordings, or video files. For live audio, see the [real-time Voice API](/docs/voice/overview).

## Prerequisites

- A DeepL API account with Voice Translate Job API access
- A pre-recorded audio file (MP3, WAV, or another [supported format](/api-reference/jobs-voice-translate/reference#supported-source-audio-formats))
- Your DeepL API key

## The four-step workflow

Translating a file always follows the same four steps:

1. Create a job and receive an upload URL
2. Upload your audio file directly to that URL
3. Poll the job status until each target is complete
4. Download the results

The examples below use `https://api.deepl.com`. If you're on an API Free plan, replace this with `https://api-free.deepl.com`.

## Step 1: Create the job

Send a POST request with your source file metadata and one or more translation targets. You can request multiple output types in a single job — for example, a German plain-text transcript and a Spanish audio file from the same English source.

```bash
curl -X POST https://api.deepl.com/v1/jobs/voice/translate \
  -H "Authorization: DeepL-Auth-Key YOUR_AUTH_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "source_file": {
      "name": "podcast-episode-42.mp3",
      "content_type": "audio/mpeg",
      "content_length": 15728640
    },
    "parameters": {
      "source_language": "en"
    },
    "targets": [
      { "language": "de", "type": "text/plain" },
      { "language": "es", "type": "audio/pcm;encoding=s16le;rate=16000" }
    ]
  }'
```

The `content_length` must match the exact byte size of the file you'll upload. The `content_type` must be a [supported audio format](/api-reference/jobs-voice-translate/reference#supported-source-audio-formats).

A successful response contains three fields:

```json
{
  "job_id": "a74d88fb-ed2a-4943-a664-a4512398b994",
  "upload_url": "https://assets.deepl.com/collections/a74d88fb-ed2a-4943-a664-a4512398b994/assets/b1c2d3e4-f5a6-7890-abcd-ef1234567890",
  "signature": "eyJhbGciOiJIUzI1NiIs..."
}
```

Save the `job_id` — you'll need it to poll for status. The `upload_url` is a pre-signed URL; save that too.

<Warning>
  You have 5 minutes to upload your file after creating a job. If the upload window expires, the job is abandoned and you'll need to create a new one.
</Warning>

## Step 2: Upload the audio file

PUT your audio file directly to the `upload_url` from the previous step. Do not include your DeepL API key in this request.

```bash
curl -X PUT "https://assets.deepl.com/collections/a74d88fb-ed2a-4943-a664-a4512398b994/assets/b1c2d3e4-f5a6-7890-abcd-ef1234567890" \
  -H "Content-Type: audio/mpeg" \
  -H "Content-Length: 15728640" \
  --data-binary @podcast-episode-42.mp3
```

The `Content-Type` and `Content-Length` headers must match the values you declared in Step 1. A mismatch will cause the upload to be rejected.

## Step 3: Poll for job status

After your file is uploaded, DeepL begins processing. Check the job status by polling the status endpoint with your `job_id`.

```bash
curl https://api.deepl.com/v1/jobs/voice/translate/a74d88fb-ed2a-4943-a664-a4512398b994 \
  -H "Authorization: DeepL-Auth-Key YOUR_AUTH_KEY"
```

While processing, the response looks like this:

```json
{
  "job_id": "a74d88fb-ed2a-4943-a664-a4512398b994",
  "operation": "translate",
  "product": "voice",
  "created_at": "2026-10-01T01:03:03.444Z",
  "updated_at": "2026-10-01T04:03:03.333Z",
  "parameters": { "source_language": "en" },
  "source_file": {
    "name": "podcast-episode-42.mp3",
    "content_type": "audio/mpeg",
    "content_length": 15728640
  },
  "targets": [
    { "language": "de", "type": "text/plain" },
    { "language": "es", "type": "audio/pcm;encoding=s16le;rate=16000" }
  ],
  "results": [
    { "status": "processing" },
    { "status": "processing" }
  ]
}
```

Results are returned in the same order as the targets in your create request. Each target transitions through its own status independently: `pending` → `uploaded` → `processing` → `complete`. A target can also transition to `failed` from any non-terminal state.

Poll every 5–10 seconds with exponential backoff until all results reach a terminal status (`complete`, `failed`, or `downloaded`). For files close to the 3-hour or 1 GB limit, allow up to 30 minutes of polling before treating the job as stalled.

When a target completes, its result entry gains a `download_url` and `signature`:

```json
{
  "results": [
    {
      "status": "complete",
      "download_url": "https://assets.deepl.com/collections/a74d88fb/assets/c3d4e5f6",
      "signature": "eyJhbGciOiJIUzI1NiIs..."
    },
    {
      "status": "failed",
      "error": { "message": "processing failed" }
    }
  ]
}
```

Notice that the two targets here reached different terminal states. A failure on one target doesn't affect the others — check each result individually.

## Step 4: Download the results

When a target's status is `complete`, use the `download_url` from the status response to fetch the result.

```bash
curl -o translation-de.txt \
  "https://assets.deepl.com/collections/a74d88fb/assets/c3d4e5f6"
```

No API key is required to download. The `download_url` is a pre-signed URL that is valid for 1 hour after the upload completes.

<Warning>
  Download each result promptly. After you download a result, its status transitions to `downloaded` and the asset is marked for deletion. Once deleted, the job returns `404`.
</Warning>

## Handling partial failures

When one target fails and others succeed, download the successful targets and decide whether to resubmit a new job for the failed ones. The `error.message` field describes what went wrong.

## Checking limits

Before submitting large batches, review the [limits](/api-reference/jobs-voice-translate/reference#limits) — including the maximum file size (1 GB), maximum source duration (3 hours), and the cap on concurrent jobs. Source audio longer than 3 hours is rejected at job creation even if the file is under 1 GB. Split longer recordings into separate jobs.
